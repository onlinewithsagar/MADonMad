Unit 1: Architecture, Lifecycles & Deployment

Android Architecture: The 5-Layer Stack 10M

GeeksforGeeks describes Android's architecture as a Linux-based software stack. Understanding how these layers interact is a guaranteed high-mark question.

5. Applications 📱
4. Application Framework (Java/Kotlin API) 🛠️
3. Android Runtime (ART) & Native Libraries ⚙️
2. Hardware Abstraction Layer (HAL) 🔗
1. Linux Kernel 🐧
  • Linux Kernel: Acts as an abstraction layer between hardware and upper layers. Manages Memory, Processes, and Device Drivers (Display, Camera, Bluetooth).
  • Hardware Abstraction Layer (HAL): Provides standard interfaces exposing hardware capabilities to the higher-level API framework.
  • ART & Native Libraries: Uses Ahead-Of-Time (AOT) compilation, translating bytecode into native machine code during installation. Results in faster app launches over legacy DVM (JIT). Native libraries include SQLite, OpenGL ES.
  • Application Framework: Toolkit for developers (ActivityManager, ViewSystem, ContentProviders).
Activity Lifecycle: State Machine Breakdown 8M

An Activity is a single, focused thing that the user can do. The OS strictly manages its states to preserve battery and memory.

  • Active/Running State: Activity is on screen and holds user focus (onResume()).
  • Paused State: Visible but lacks focus (e.g., a transparent dialog is over it). Alive in memory but can be killed if RAM is critically low (onPause()).
  • Stopped State: Completely hidden by another activity. Retained in memory but no execution (onStop()).

Handling Screen Orientation

Rotation destroys and recreates the Activity: onPause() → onStop() → onDestroy() → onCreate() → onStart() → onResume().

To prevent data loss, developers must use onSaveInstanceState() to bundle data before destruction.

Intents, Data Passing & AndroidManifest 5M

Explicit vs Implicit Intents

  • Explicit Intent: Specifies the exact Activity class to open. Used for internal navigation. 
    Intent intent = new Intent(this, SecondActivity.class);
intent.putExtra("key", "value"); // Passing Data
startActivity(intent);
  • Implicit Intent: Declares a general action and lets the OS find an app to handle it. 
    Intent intent = new Intent(Intent.ACTION_VIEW);
intent.setData(Uri.parse("https://bcu.ac.in"));
startActivity(intent);

AndroidManifest.xml

The structural blueprint read by the OS. It declares components, requests permissions (<uses-permission>), and sets the entry point using an intent-filter with MAIN and LAUNCHER.

Publishing & APK Generation Steps 5M
  1. Go to Build → Generate Signed Bundle / APK in Android Studio.
  2. Select APK (or App Bundle).
  3. Under Key store path, click Create new... and fill in Keystore details (Password, Alias, Validity).
  4. Select the Destination Folder and choose Build Variants (Release).
  5. Select Signature Versions (V1/V2) and click Finish.
  6. Upload the generated Signed Release APK to the Google Play Console after creating a Developer Account.

Unit 2 & 3: UI, Layouts, Fragments & Dialogs

Layout Performance: Linear vs Constraint 8M
  • LinearLayout: Arranges children in a single row or column. Easy to use but causes performance issues if deeply nested (The Measurement Problem).
  • ConstraintLayout: The ultimate solution. Creates a flat view hierarchy. Elements have rules attaching them to parent/sibling elements, eliminating deep nesting and maximizing rendering performance.
<androidx.constraintlayout.widget.ConstraintLayout>
    <TextView android:id="@+id/title" app:layout_constraintTop_toTopOf="parent" />
    <!-- Button directly anchors to TextView below -->
    <Button app:layout_constraintTop_toBottomOf="@id/title" />
</androidx.constraintlayout.widget.ConstraintLayout>
Fragments, Menus & Dialogs 5M/8M

Fragments

A modular, reusable sub-section of an Activity. Managed via FragmentManager.

FragmentTransaction tx = getSupportFragmentManager().beginTransaction();
tx.replace(R.id.container, new HomeFragment());
tx.commit();

Menus

  • Options Menu: Global menu (top right). Programmed via onCreateOptionsMenu().
  • Context Menu: Tied to a View. Invoked by long-pressing. Programmed via onCreateContextMenu().

Dialogs

AlertDialog: Standard popup for warnings/choices. DatePickerDialog: UI to select dates.

Unit 4: Database, Providers, Services & Networking

SQLite Database: Cursors and CRUD Workflow 8M/10M

Local data persistence using SQLiteOpenHelper requires understanding the Cursor object. A Cursor provides random read-write access to database query results.

// 1. CREATE Table (in onCreate)
db.execSQL("CREATE TABLE users(id INTEGER PRIMARY KEY, name TEXT)");

// 2. INSERT
ContentValues cv = new ContentValues();
cv.put("name", "John");
db.insert("users", null, cv);

// 3. READ (Using Cursor)
public ArrayList<String> getAllUsers() {
    ArrayList<String> list = new ArrayList<>();
    SQLiteDatabase db = this.getReadableDatabase();
    Cursor cursor = db.rawQuery("SELECT * FROM users", null);
    
    if (cursor.moveToFirst()) {
        do { list.add(cursor.getString(1)); } while (cursor.moveToNext()); 
    }
    cursor.close(); db.close(); // Prevent leaks!
    return list;
}
Content Providers (IPC) & SharedPreferences 8M

Content Providers

A standard interface connecting data in one process with code running in another.

  • The Source: An app exposes internal SQLite tables safely.
  • The Request: Custom app uses ContentResolver to ask the system for data.
  • The Bridge (URI): content://<authority>/<path>/<id> routes the request.

SharedPreferences

Stores primitive data in XML files. Use apply() for async writing (recommended) instead of commit() (sync UI blocking).

Networking, Background Threads & Notifications High Yield

Networking & JSON Parsing

Android strictly forbids network operations on the Main UI Thread (NetworkOnMainThreadException). Use HttpURLConnection in a background thread to fetch data, then parse using JSONObject.

Background Threads (AsyncTask vs Coroutines)

  • AsyncTask: Legacy, deprecated method due to memory leaks. Provided doInBackground() and onPostExecute().
  • Kotlin Coroutines / ExecutorService: The modern standard. Lightweight threads that execute background tasks without blocking the UI.

Notifications (API 26+)

Since Android 8.0 (Oreo), notifications must be assigned to a NotificationChannel via the NotificationManager, allowing users to control specific types of alerts rather than blocking the entire app.

Services, Location Providers & Sensors 5M/8M

Services

  • Started: Runs indefinitely (e.g., file download).
  • Bound: Client-Server interface. Runs while bounded to an Activity.
  • Foreground: Must display a status bar notification (e.g., Music Player).

Location Services & Sensors

Use FusedLocationProviderClient for battery-efficient GPS tracking over the legacy LocationManager. Hardware sensors (like Accelerometer) are accessed using SensorManager and implementing a SensorEventListener.

Flashcards: 2-Mark Question Bank

Part A & Section A (Rapid Fire Definitions) Flashcards

Web App vs Native App

Native apps are built specifically for a platform (Java/Kotlin) with full hardware access. Web apps run in a browser with restricted access.

Android Activity

An Activity represents a single, independent screen with a user interface. Its primary function is to handle user interactions.

Dalvik Virtual Machine (DVM)

DVM is the legacy Android runtime using Just-In-Time (JIT) compilation. Replaced by ART (Ahead-Of-Time compilation) in modern Android.

ViewGroup

An invisible container that holds other Views. Common implementations: LinearLayout, ConstraintLayout, RelativeLayout.

Geocoding & GPS

Geocoding converts addresses to Lat/Long coordinates. Reverse Geocoding converts coordinates back to addresses. GPS provides the raw device location.

BroadcastReceiver

A component that listens for and responds to system-wide broadcast announcements (e.g., "Battery Low", "Boot Completed").

Logcat Window

A diagnostic tool in Android Studio displaying system messages, stack traces, and custom log outputs (Log.d()) in real-time.

Permissions (Normal vs Dangerous)

Normal permissions (Internet) are auto-granted. Dangerous permissions (Camera, Location) access private user data and must be requested at runtime (API 23+).

ContentResolver

The client-side object used to communicate with a ContentProvider, allowing apps to securely query and modify shared data via a URI.

Exam Formatting Strategy

How to maximize your marks according to evaluator psychology.

2-Mark Questions ⚡

Rule: Get in, define, get out.

Write exactly 2 to 3 sentences. No diagrams. No code unless explicitly asked.

  • Sentence 1: Technical definition.
  • Sentence 2: Primary purpose / real-world analogy.

5-Mark Questions 📄

Rule: Structure over length.

Target 1 to 1.5 pages. Break answer into strict sub-headings.

  • Header 1: Definition & Purpose.
  • Header 2: Core Components (bullet points).
  • Header 3: 4-5 line core code snippet. Underline keywords.

8/10-Mark Questions 📐

Rule: The Blueprint Approach.

Target 2.5 to 3 pages. Requires architectural depth.

  • Phase 1: Introduction.
  • Phase 2: Neat block diagram (Boxed).
  • Phase 3: Component breakdown.
  • Phase 4: Substantial commented code block.
