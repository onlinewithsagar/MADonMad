Unit 1: Architecture & Deployment
Android Architecture: The 5-Layer Stack 10M

GeeksforGeeks describes Android's architecture as a Linux-based software stack. Understanding how these layers interact is a guaranteed high-mark question.

5. System & User Applications
4. Application Framework (Java/Kotlin API)
3. Android Runtime (ART) & Native Libraries
2. Hardware Abstraction Layer (HAL)
1. Linux Kernel
  • Linux Kernel: Acts as an abstraction layer between hardware and upper layers. Manages Memory, Processes, and Device Drivers (Display, Camera, Bluetooth, Audio). Analogy: The foundation and wiring of a house.
  • Hardware Abstraction Layer (HAL): Provides standard interfaces exposing hardware capabilities to the higher-level Java API framework.
  • ART & Native Libraries: Uses Ahead-Of-Time (AOT) compilation, translating your app's bytecode into native machine code during installation. Results in faster app launches over legacy DVM (JIT). Includes SQLite, OpenGL ES.
  • Application Framework: Toolkit for developers (ActivityManager, ViewSystem, ContentProviders).
  • Applications: Where your compiled `.apk` resides alongside system apps.
Activity Lifecycle: State Machine Breakdown 8M

An Activity is a single, focused thing that the user can do. The OS strictly manages its states to preserve battery and memory.

  • Active/Running State: Activity is on screen and holds user focus (onResume()).
  • Paused State: Visible but lacks focus (e.g., a transparent dialog is over it). Alive in memory but can be killed if RAM is critically low (onPause()).
  • Stopped State: Completely hidden by another activity. Retained in memory but no execution (onStop()).

GfG Real-Life Scenario Triggers

Scenario: User filling out a form, and a phone call comes in.
1. App is Running: onResume()
2. Call Screen Appears: onPause() (Save the user's form text here!).
3. Call goes full screen: onStop()
4. Call ends, user returns: onRestart() → onStart() → onResume().

Handling Screen Orientation

Rotation destroys and recreates the Activity: onPause() → onStop() → onDestroy() → onCreate() → onStart() → onResume().

To prevent data loss, developers must use onSaveInstanceState().

Intents, Data Passing & AndroidManifest 5M

Explicit vs Implicit Intents

An Intent is a messaging object used to request an action from another app component.

  • Explicit Intent: Specifies the exact Activity class to open. Used for internal navigation. 
    Intent intent = new Intent(this, SecondActivity.class);
intent.putExtra("key", "value"); // Passing Data
startActivity(intent);
  • Implicit Intent: Declares a general action (like opening a URL) and lets the OS find an app to handle it. 
    Intent intent = new Intent(Intent.ACTION_VIEW);
intent.setData(Uri.parse("https://geeksforgeeks.org"));
startActivity(intent);

AndroidManifest.xml

The structural blueprint read by the OS before execution. It declares components, requests permissions (<uses-permission>), and sets the entry point using an intent-filter.

Publishing & APK Generation Steps Process

Generating a Signed APK in Android Studio

  1. Go to Build → Generate Signed Bundle / APK.
  2. Select APK (or Android App Bundle).
  3. Under Key store path, click Create new...
  4. Fill in the Keystore details (Password, Alias, Validity, Certificate info).
  5. Select the Destination Folder and choose Build Variants (Release).
  6. Select Signature Versions (V1 Jar Signature, V2 Full APK Signature) and click Finish.

Publishing on Google Play Store

  1. Create a Google Play Developer Account (pay $25 fee).
  2. Create an App Profile (Title, description, screenshots, high-res icon).
  3. Upload the Signed Release APK or AAB.
  4. Complete Content Rating Questionnaire.
  5. Set Pricing and Distribution regions.
  6. Click Rollout to Production to submit for review.
Unit 2 & 3: UI, Layouts & Fragments
Layout Performance: Linear vs Constraint vs Relative 8M
  • LinearLayout: Arranges children in a single row or column. Easy to use but causes performance issues if deeply nested (The Measurement Problem/Double Taxation).
  • RelativeLayout: Anchors elements relative to each other (e.g., layout_below). More flexible but still requires two measurement passes.
  • ConstraintLayout: The ultimate solution. Creates a flat view hierarchy. Every UI element has rules attaching it to parent or sibling elements, eliminating deep nesting and maximizing rendering performance.
<androidx.constraintlayout.widget.ConstraintLayout>
    <TextView android:id="@+id/titleText"
              app:layout_constraintTop_toTopOf="parent" />
    <!-- Button directly anchors to TextView below -->
    <Button android:id="@+id/submitBtn"
            app:layout_constraintTop_toBottomOf="@id/titleText" />
</androidx.constraintlayout.widget.ConstraintLayout>
Fragments, Menus & UI Controls 5M/8M

Fragments

A modular, reusable sub-section of an Activity. Unlike an Activity (an independent window), a Fragment must be hosted inside an Activity. Managed via FragmentManager.

FragmentTransaction tx = getSupportFragmentManager().beginTransaction();
tx.replace(R.id.container, new HomeFragment());
tx.commit();

Menus: Options vs Context

  • Options Menu: Global menu (top right, 3 dots). Invoked by OS. Programmed via onCreateOptionsMenu().
  • Context Menu: Tied to a specific View. Invoked by user long-pressing the View. Programmed via onCreateContextMenu().

UI Pickers

DatePicker / TimePicker: Controls ensuring valid user input for dates/times. Typically wrapped in DatePickerDialog or TimePickerDialog.

Unit 4: Database & Background Services
SQLite Database: Cursors and CRUD Workflow 8M/10M

Local data persistence using SQLiteOpenHelper requires understanding the Cursor object. A Cursor provides random read-write access to database query results.

CRUD Code Snippets (GfG Standard)

// 1. CREATE Table (in onCreate of SQLiteOpenHelper)
db.execSQL("CREATE TABLE users(id INTEGER PRIMARY KEY, name TEXT)");

// 2. INSERT (Create)
ContentValues cv = new ContentValues();
cv.put("name", "John");
db.insert("users", null, cv);

// 3. READ (Using Cursor)
public ArrayList<String> getAllUsers() {
    ArrayList<String> list = new ArrayList<>();
    SQLiteDatabase db = this.getReadableDatabase();
    Cursor cursor = db.rawQuery("SELECT * FROM users", null);
    
    if (cursor.moveToFirst()) {
        do {
            list.add(cursor.getString(1)); // Column 1 is Name
        } while (cursor.moveToNext()); 
    }
    cursor.close(); db.close(); // Prevent leaks!
    return list;
}
SharedPreferences & Content Providers (IPC) 5M/8M

SharedPreferences: Sync vs Async

Stores primitive data in internal XML files.

  • commit(): Writes synchronously (UI thread). Returns boolean.
  • apply(): Writes asynchronously in background. GfG recommended.

Content Providers (IPC)

A standard interface connecting data in one process with code running in another.

  • The Source: An app exposes internal SQLite tables safely via a Provider.
  • The Request: Custom app uses ContentResolver to ask the system for data.
  • The Bridge (URI): content://<authority>/<path>/<id> routes the request.
Services, Web APIs & Google Maps 5M/8M

Services

  • Started: Runs indefinitely (e.g., download). startService()
  • Bound: Client-Server interface. Runs while bound.
  • Foreground: Must display status bar notification (OS prioritizes heavily).

Consuming Web Services

Network Thread Rule: Never run network operations on the Main UI Thread (throws NetworkOnMainThreadException). Use background threads (Coroutines/AsyncTask) to open an HttpURLConnection, read the InputStream, and parse the JSON response.

Google Maps Integration Workflow

  1. Get Google Maps API key from Google Cloud Console.
  2. Add Dependencies in build.gradle.
  3. Add API key inside <meta-data> tag and location permissions in AndroidManifest.xml.
  4. Add SupportMapFragment in XML layout.
  5. Implement OnMapReadyCallback in the Activity to manipulate the map.

Section A (2-Mark Definitions) Quick Review

Web App vs Native App

Native apps are built specifically for a platform (Java/Kotlin for Android) with full hardware access. Web apps run in a browser and are cross-platform but have restricted hardware access.

Android Activity

An Activity represents a single, independent screen with a user interface. Its primary function is to handle user interactions and display views.

Dalvik Virtual Machine (DVM) vs ART

DVM is the legacy Android runtime using Just-In-Time (JIT) compilation. ART (Android Runtime) replaced it, using Ahead-Of-Time (AOT) compilation for faster execution.

ViewGroup

A ViewGroup is an invisible container that holds other Views or ViewGroups. Common implementations: LinearLayout, ConstraintLayout.

Geocoding vs Reverse Geocoding

Geocoding converts human-readable addresses (e.g., "Bengaluru") to Lat/Long coordinates. Reverse Geocoding converts coordinates back into physical addresses.

BroadcastReceiver

A component that listens for and responds to system-wide broadcast announcements (e.g., "Battery Low" or "Wi-Fi changed").

Logcat Window

A diagnostic tool in Android Studio that displays system messages, stack traces, and custom log outputs (e.g., Log.d()) in real-time.

MCQ Quick Facts

  • Stores key-value primitive data: SharedPreferences
  • Not a core component: Fragment
  • File declaring all components: AndroidManifest.xml

Exam Formatting Strategy

How to maximize your marks according to evaluator psychology.

2-Mark Questions

Rule: Get in, define, get out.

Write exactly 2 to 3 sentences. No diagrams. No code unless explicitly asked.

  • Sentence 1: Technical definition.
  • Sentence 2: Primary purpose / real-world analogy.

5-Mark Questions

Rule: Structure over length.

Target 1 to 1.5 pages. Break answer into strict sub-headings.

  • Header 1: Definition & Purpose.
  • Header 2: Core Components (bullet points).
  • Header 3: 4-5 line core code snippet. Underline keywords.

8/10-Mark Questions

Rule: The Blueprint Approach.

Target 2.5 to 3 pages. Requires architectural depth.

  • Phase 1: Introduction.
  • Phase 2: Neat block diagram (Boxed).
  • Phase 3: Component breakdown.
  • Phase 4: Substantial commented code block.
