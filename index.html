Unit 1: Architecture, Lifecycles & Deployment

Android Architecture: The 5-Layer Stack 10M

GeeksforGeeks describes Android's architecture as a Linux-based software stack.

5. System & User Applications
4. Application Framework (Java/Kotlin API)
3. Android Runtime (ART) & Native Libraries
2. Hardware Abstraction Layer (HAL)
1. Linux Kernel
  • Linux Kernel: Acts as an abstraction layer between hardware and upper layers. Manages Memory, Processes, and Device Drivers (Display, Camera, Bluetooth, Audio). Analogy: The foundation and wiring of a house.
  • Hardware Abstraction Layer (HAL): Provides standard interfaces exposing hardware capabilities to the higher-level Java API framework.
  • ART & Native Libraries: Uses Ahead-Of-Time (AOT) compilation, translating bytecode into machine code during installation. Includes C/C++ libraries like SQLite, OpenGL ES.
  • Application Framework: Toolkit for developers (ActivityManager, ViewSystem, ContentProviders).
  • Applications: Where your compiled `.apk` resides alongside system apps.
Android Runtime (ART) vs Dalvik Virtual Machine (DVM) 5M

Dalvik Virtual Machine (DVM)

The legacy Android runtime used before Android 5.0. It utilizes Just-In-Time (JIT) compilation, meaning it compiles bytecode into machine code dynamically every time the application is run. This takes up less storage space but causes higher CPU usage and battery drain.

Android Runtime (ART)

The modern execution environment. It uses Ahead-Of-Time (AOT) compilation. It compiles the bytecode once into native machine code directly during app installation. While it takes up more storage space, it significantly improves app launch speeds and battery efficiency.

Activity Lifecycle & Component States 8M/10M

An Activity is a single, focused thing that the user can do. The OS strictly manages its states to preserve battery and memory.

  • Active/Running State: Activity is on screen and holds user focus (onResume()).
  • Paused State: Visible but lacks focus (e.g., a transparent dialog is over it). Alive in memory but can be killed if RAM is critically low (onPause()).
  • Stopped State: Completely hidden by another activity. Retained in memory but no execution (onStop()).

Handling Screen Orientation

Rotation destroys and recreates the Activity: onPause() → onStop() → onDestroy() → onCreate() → onStart() → onResume().

To prevent data loss, developers must use onSaveInstanceState().

Explicit vs Implicit Intents & Invocation 5M

Explicit Intents

Explicitly specifies the exact Activity class to open. Used for internal navigation.

Intent intent = new Intent(this, SecondActivity.class);
intent.putExtra("key_name", "Data String"); // Passing Data
startActivity(intent);

Implicit Intents (Invoking Built-in Apps)

Specifies an action (what to do) allowing the Android OS to find a suitable external app to handle it.

// Example: Opening a Web Browser
Intent intent = new Intent(Intent.ACTION_VIEW);
intent.setData(Uri.parse("https://www.geeksforgeeks.org"));
startActivity(intent);
Publishing & APK Generation Steps 5M/8M

Generating a Signed APK

  1. Go to Build → Generate Signed Bundle / APK.
  2. Select APK.
  3. Under Key store path, click Create new...
  4. Fill in the Keystore details (Password, Alias).

Unit 2 & 3: UI, Layouts, Fragments & Dialogs

Views, ViewGroups & Anchoring Attributes 5M

View vs ViewGroup

View: The basic building block of a UI (e.g., Button, TextView, EditText). It occupies a rectangular area on the screen and handles drawing and events.

ViewGroup: An invisible container that holds multiple Views or other ViewGroups to define layout structure (e.g., LinearLayout, RelativeLayout).

Anchoring Views (RelativeLayout)

Anchoring refers to positioning a UI element relative to the physical edges of its parent container or in relation to sibling elements within the same layout.

  • android:layout_alignParentTop="true": Anchors the view to the top edge of the parent.
  • android:layout_below="@+id/header": Anchors the view directly beneath the 'header' sibling.
  • android:layout_toRightOf="@+id/icon": Anchors the view to the right side of the 'icon' sibling.
Layout Performance: Linear vs Constraint vs Relative 8M
  • LinearLayout: Arranges children in a single row or column. Causes performance issues if deeply nested (The Measurement Problem).
  • RelativeLayout: Anchors elements relative to each other (e.g., layout_below). Requires two measurement passes by the OS.
  • ConstraintLayout: Creates a flat view hierarchy. Every UI element has rules attaching it to parent or sibling elements, eliminating deep nesting and maximizing rendering performance.
Login Form Validation Code 8M

To validate user login details ensuring fields are not empty, we utilize Android's `TextUtils.isEmpty()` method within a button click listener.

Button loginBtn = findViewById(R.id.btnLogin);
EditText userField = findViewById(R.id.etUsername);
EditText passField = findViewById(R.id.etPassword);

loginBtn.setOnClickListener(new View.OnClickListener() {
    @Override
    public void onClick(View v) {
        String username = userField.getText().toString().trim();
        String password = passField.getText().toString().trim();

        if (TextUtils.isEmpty(username)) {
            userField.setError("Username cannot be empty");
            return; // Stop execution
        }
        if (TextUtils.isEmpty(password)) {
            passField.setError("Password cannot be empty");
            return; // Stop execution
        }
        
        Toast.makeText(MainActivity.this, "Validation Success!", Toast.LENGTH_SHORT).show();
    }
});
Fragments, Menus & Dialogs 5M/8M

Fragments vs Activity

A Fragment is a modular, reusable sub-section of a UI. Unlike an Activity (which is an independent window managed by the OS), a Fragment must be hosted inside an Activity. It is managed via FragmentManager.

Menus: Options vs Context

  • Options Menu: Global menu (top right, 3 dots). Invoked by OS. Programmed via onCreateOptionsMenu().
  • Context Menu: Tied to a specific View. Invoked by user long-pressing the View. Programmed via onCreateContextMenu().

Unit 4: Database, Providers, Services & Networking

Comparison: Data Storage Options in Android 5M

Android provides several options to persist application data, chosen based on data structure and accessibility needs:

  • SharedPreferences: Use this to store private, small primitive data in key-value pairs (e.g., user settings, login tokens).
  • Internal File Storage: Use this to store private files directly on the device memory. Files are inaccessible to other apps and removed on uninstall.
  • External File Storage: Use this to store public or shared files (like photos/downloads) on the shared external storage (SD Card). Requires runtime permissions.
  • SQLite Databases: Use this to store structured, relational data privately (e.g., user records, offline caches).
  • Content Providers: Use this exclusively when you need to expose your private app data to other external applications securely.
SQLite Database: CRUD Workflow & Advantages 8M/10M

Advantages & Disadvantages

  • Advantages: Serverless (Zero-Configuration), Lightweight (single file), ACID Compliant (secure transactions).
  • Disadvantages: Poor Concurrency (only one writer at a time), No User Management/Access Control, Limited capacity for massive enterprise data.

CRUD Code Snippets

// 1. CREATE Table
db.execSQL("CREATE TABLE users(id INTEGER PRIMARY KEY, name TEXT)");

// 2. INSERT (Create)
ContentValues cv = new ContentValues();
cv.put("name", "John");
db.insert("users", null, cv);

// 3. READ (Using Cursor)
public ArrayList<String> getAllUsers() {
    ArrayList<String> list = new ArrayList<>();
    SQLiteDatabase db = this.getReadableDatabase();
    Cursor cursor = db.rawQuery("SELECT * FROM users", null);
    
    if (cursor.moveToFirst()) {
        do { list.add(cursor.getString(1)); } while (cursor.moveToNext()); 
    }
    cursor.close(); db.close(); 
    return list;
}
Four Core Components & Broadcast Receivers 10M

Four Core Application Components

  • Activities: The UI presentation layer representing a single screen.
  • Services: Background processing workhorses (no UI).
  • Broadcast Receivers: System-wide event listeners.
  • Content Providers: Secure inter-process data sharing managers.

Broadcast Receiver: Real-World Example

A Broadcast Receiver listens for global events. For example, registering a receiver to listen for Intent.ACTION_BATTERY_LOW. When triggered, the receiver can automatically pause heavy background downloads to save power, or listening for Intent.ACTION_AIRPLANE_MODE_CHANGED to alert the user that network calls will fail.

AsyncTask, Notifications & Media Playback 8M

AsyncTask (Deprecated)

Used to perform short background operations (like fetching network data) and publish results on the UI thread without manipulating threads directly (doInBackground(), onPostExecute()). Deprecated due to memory leaks; Kotlin Coroutines are the modern standard.

Notifications (API 26+)

Since Android 8.0, you must implement a NotificationChannel to group alerts, allowing users to selectively block them.

NotificationChannel channel = new NotificationChannel("id", "Name", NotificationManager.IMPORTANCE_HIGH);
manager.createNotificationChannel(channel);

Media Playback (MediaPlayer)

Controls playback of audio/video files. Highly state-sensitive. You MUST release resources when the Activity dies to prevent severe memory leaks (mediaPlayer.release() in onDestroy()).

Google Maps Integration & Location Services 8M

Google Maps Integration Workflow

  1. Get Google Maps API key from Google Cloud Console.
  2. Add Dependencies in build.gradle.
  3. Add API key inside <meta-data> tag and location permissions in AndroidManifest.xml.
  4. Add SupportMapFragment in XML layout.
  5. Implement OnMapReadyCallback in the Activity to manipulate the map.

Location Services (LBS)

Use FusedLocationProviderClient (Google Play Services) instead of legacy LocationManager for battery efficiency. Features include Geofencing, Mapping, and POI discovery.

Exam Formatting Strategy

How to maximize your marks according to evaluator psychology.

2-Mark Questions

Rule: Get in, define, get out.

Write exactly 2 to 3 sentences. No diagrams. No code unless explicitly asked.

  • Sentence 1: Technical definition.
  • Sentence 2: Primary purpose / real-world analogy.

5-Mark Questions

Rule: Structure over length.

Target 1 to 1.5 pages. Break answer into strict sub-headings.

  • Header 1: Definition & Purpose.
  • Header 2: Core Components (bullet points).
  • Header 3: 4-5 line core code snippet. Underline keywords.

8/10-Mark Questions

Rule: The Blueprint Approach.

Target 2.5 to 3 pages. Requires architectural depth.

  • Phase 1: Introduction.
  • Phase 2: Neat block diagram (Boxed).
  • Phase 3: Component breakdown.
  • Phase 4: Substantial commented code block.
