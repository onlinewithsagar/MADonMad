Unit 1: Architecture & Deployment
Android Architecture: The 5-Layer Stack 10M

GeeksforGeeks describes Android's architecture as a Linux-based software stack. Understanding how these layers interact is a guaranteed high-mark question.

5. System & User Applications
4. Application Framework (Java/Kotlin API)
3. Android Runtime (ART) & Native Libraries
2. Hardware Abstraction Layer (HAL)
1. Linux Kernel
  • Linux Kernel: Acts as an abstraction layer between hardware and upper layers. Manages Memory, Processes, and Device Drivers (Display, Camera). Analogy: The foundation and wiring of a house.
  • Hardware Abstraction Layer (HAL): Provides standard interfaces exposing hardware capabilities to the higher-level API.
  • ART & Native Libraries: Uses Ahead-Of-Time (AOT) compilation, translating your app's bytecode into native machine code. Results in faster app launches.
  • Application Framework: Toolkit for developers (ActivityManager, ViewSystem, ContentProviders).
  • Applications: Where your compiled `.apk` resides.
Activity Lifecycle: State Machine Breakdown 95% Prob

An Activity is a single, focused thing that the user can do. The OS strictly manages its states to preserve battery and memory.

  • Active/Running State: Activity is on screen and holds user focus (onResume()).
  • Paused State: Visible but lacks focus (e.g., a dialog is over it). Alive in memory (onPause()).
  • Stopped State: Completely hidden by another activity. Retained in memory but no execution (onStop()).

GfG Real-Life Scenario Triggers

Scenario: User filling out a form, and a phone call comes in.
1. App is Running: onResume()
2. Call Screen Appears: onPause() (Save user form text here!).
3. Call goes full screen: onStop()
4. Call ends, user returns: onRestart() → onStart() → onResume().

Handling Screen Orientation

Rotation destroys and recreates the Activity. To prevent data loss, developers must use onSaveInstanceState().

Intents, Data Passing & AndroidManifest 5M

Explicit vs Implicit Intents

An Intent is a messaging object used to request an action.

  • Explicit Intent: Specifies the exact Activity class. Used for internal navigation. 
    Intent intent = new Intent(this, SecondActivity.class);
intent.putExtra("key", "value"); // Passing Data
startActivity(intent);
  • Implicit Intent: Declares a general action and lets the OS find an app. 
    Intent intent = new Intent(Intent.ACTION_VIEW);
intent.setData(Uri.parse("https://geeksforgeeks.org"));
startActivity(intent);

AndroidManifest.xml

The blueprint read by the OS. Declares components, permissions, and sets the entry point using an intent-filter.

Unit 2 & 3: UI & Fragments
Layout Performance: Linear vs Constraint 8M
  • LinearLayout: Arranges children in a single row or column. Causes performance issues if deeply nested (Double Taxation).
  • ConstraintLayout: Creates a flat view hierarchy. Every UI element has rules attaching it to parent or sibling elements, maximizing performance.
<androidx.constraintlayout.widget.ConstraintLayout>
    <TextView android:id="@+id/titleText"
              app:layout_constraintTop_toTopOf="parent" />
    <!-- Button directly anchors to TextView below -->
    <Button android:id="@+id/submitBtn"
            app:layout_constraintTop_toBottomOf="@id/titleText" />
</androidx.constraintlayout.widget.ConstraintLayout>
Fragments, Menus & Dialogs

Fragments

A modular sub-section of an Activity. Managed via FragmentManager.

FragmentTransaction tx = getSupportFragmentManager().beginTransaction();
tx.replace(R.id.container, new HomeFragment());
tx.commit();

Menus & Dialogs

  • Options Menu: Global menu. onCreateOptionsMenu().
  • Context Menu: Tied to a specific View via long-press.
  • Dialogs: AlertDialog (Confirmations), DatePickerDialog (Input).
Unit 4: Database & Services
SQLite Database: Cursors and CRUD Workflow 8M/10M

Local data persistence using SQLiteOpenHelper requires understanding the Cursor object. A Cursor provides random read-write access to query results.

// 1. CREATE Table (in onCreate)
db.execSQL("CREATE TABLE users(id INTEGER PRIMARY KEY, name TEXT)");

// 2. INSERT (Create)
ContentValues cv = new ContentValues();
cv.put("name", "John");
db.insert("users", null, cv);

// 3. READ (Using Cursor)
public ArrayList<String> getAllUsers() {
    ArrayList<String> list = new ArrayList<>();
    SQLiteDatabase db = this.getReadableDatabase();
    Cursor cursor = db.rawQuery("SELECT * FROM users", null);
    
    if (cursor.moveToFirst()) {
        do {
            list.add(cursor.getString(1)); // Column 1 is Name
        } while (cursor.moveToNext()); 
    }
    cursor.close(); db.close();
    return list;
}
SharedPreferences & Content Providers 92% Prob

SharedPreferences: Sync vs Async

Stores primitive data in XML files.

  • commit(): Writes synchronously (UI thread). Can freeze UI.
  • apply(): Writes asynchronously in background. GfG recommended.

Content Providers (IPC)

Standard interface connecting data in one process with code running in another.

  • The Source: An app safely exposes SQLite tables via a Provider.
  • The Bridge (URI): content://<authority>/<path>/<id> routes the request.

Section A (2-Mark Definitions) Quick Review

Web App vs Native App

Native apps are built specifically for a platform with full hardware access. Web apps run in a browser and are cross-platform.

Android Activity

Represents a single, independent screen with a user interface to handle user interactions.

DVM vs ART

DVM uses Just-In-Time (JIT) compilation. ART uses Ahead-Of-Time (AOT) compilation for faster execution.

BroadcastReceiver

A component that listens for and responds to system-wide broadcast announcements (e.g., "Battery Low").

Exam Formatting Strategy

How to maximize your marks according to evaluator psychology.

2-Mark Questions

Rule: Get in, define, get out.

  • Write exactly 2 to 3 sentences.
  • No diagrams. No code.
  • Sentence 1: Technical definition.
  • Sentence 2: Real-world analogy.

5-Mark Questions

Rule: Structure over length.

  • Target 1 to 1.5 pages.
  • Break into strict sub-headings.
  • Include a 4-5 line core code snippet. Underline keywords.

8/10-Mark Questions

Rule: The Blueprint Approach.

  • Target 2.5 to 3 pages.
  • Phase 1: Neat block diagram (Boxed).
  • Phase 2: Component breakdown.
  • Phase 3: Substantial commented code block.
